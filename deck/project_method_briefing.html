02 · Tool choice, on purpose

Started in the tool I know, then deliberately left it

Looker Studio, built first

The dashboard tool I use daily at Momentum Data. Built the individual visuals first, mostly the ones AI suggested, then organised them into a broad-to-narrow drill-down myself, three scorecards down to business-unit detail. That structure is mine, not suggested, it's the same one I've used in academic writing, publications, my thesis, long before this project.

Power BI, built second, on purpose

Rebuilt the same model in a tool I use less. New interface, first real use of Power Query and DAX in this project, and the two double-counting traps already solved once in Looker Studio had to be re-solved from scratch in a completely different tool.

Same underlying model, two different tools. Rebuilding it twice was the point, not a shortcut taken once and reused. The traps stayed the same; how each tool needed to be told about them didn't.

03 · Solved in Power Query

A sort-order problem that took three tries to actually fix

Why Power Query, really
Wanted the region and business-unit stacked columns ordered a specific way, the same custom series sort Looker Studio supports natively. Power BI has no direct equivalent, so the first attempt was a DAX calculated column, a SWITCH-based sort order that hit a circular dependency: sorting a column by a column whose own formula reads that same column. AI suggested Power Query instead, computed at load time, before DAX's dependency graph even exists.
One column, then two, then the real fix
Built one conditional column for Printing versus Personal Systems, then a second for Supplies, Commercial and Consumer Printing. Both read the same business_unit column, and Power BI only allows one sort-by-column mapping per column, so the two couldn't coexist. Noticed that myself, then fixed it by building a third column instead, one set of conditions covering all five business units at once, five conditions total, so a single sort order works correctly no matter which chart is filtering to which subset.
What didn't work. Two ratio measures, built to show percent-of-total through filter-context override, never produced a correct result. Debugged at length, including versions with no dependency on any other measure. Root cause never identified. Time-boxed, and reverted to the version that was already correct rather than shipping something broken. That is a real answer to "what was hard here," not a gap to hide.

04 · Both decks, the same way

Built as HTML, styled to match HP's own template, exported to PDF

Styled against a real reference

Rendered pages from HP's own Q4 FY25 earnings presentation, sampled the exact blue, the type treatment, and the diagonal corner motif, this deck and the analysis deck both use it. Not a generic template, HP's own visual language.

Built and edited with AI

Every slide is plain HTML and CSS, drafted and revised with AI over several passes, real numbers checked against the same source files as the dashboards, then converted to PDF with a small HTML-to-PDF converter I built myself as a separate project.
